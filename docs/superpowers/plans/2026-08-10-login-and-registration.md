# Login-by-email and richer registration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users log in with either their username or email, and collect a required full name (plus a client-side confirm-password check) at registration.

**Architecture:** Backend: widen the login lookup to match `User.username` OR `User.email`; add a required `full_name` column to `User` via a new Alembic migration, threaded through the register route and its Pydantic/SQLModel schemas. Frontend: relabel the login field, add "Full name" and "Confirm password" fields to registration, and thread `full_name` through the API client, `AuthContext`, and the `User` type.

**Tech Stack:** FastAPI + SQLModel + Alembic (async, asyncpg) on the backend; React + TypeScript on the frontend. No persistent test suite exists in this repo — verification uses the `pgserver` (ephemeral real Postgres) + `httpx.ASGITransport` technique documented in `CLAUDE.md`, plus `npm run typecheck`/`npm run build` on the frontend.

## Global Constraints

- Backend: Python 3.12, managed with `uv`, no lint/format config exists — match existing style in the touched files.
- Frontend: `npm run typecheck` (`tsc --noEmit`) must pass; no lint config exists.
- `full_name` is a **required** field on `User` (NOT NULL column, required in `UserRegister`/registration form).
- Confirm-password on registration is a frontend-only check — no backend change for it.
- The JWT `sub` claim must keep encoding `user.username` (the resolved DB row's username), never the raw login identifier — `get_current_user` depends on this and must not be touched.
- Do not touch `Layout.tsx`'s nav avatar or any other display of `username` — out of scope per the approved spec.
- `backend/migrations/versions/` currently has an uncommitted, pre-existing modification (`7d771e25734d`'s `down_revision` was repointed after a prior migration was deleted) — leave that as-is; the new migration in this plan chains onto the current head (`7d771e25734d`) regardless of what its own git status looks like.

- [ ] **Step 1: Update `authenticate_user`'s lookup**

In `backend/app/api/routes/auth.py`, replace the query in `authenticate_user` (currently `where(User.username == username)`) with a match against either column, and rename the parameter to reflect that it's no longer username-only:

```python
async def authenticate_user(identifier: str, password: str, session: AsyncSession = Depends(get_session)):
    result = await session.execute(
        select(User).where((User.username == identifier) | (User.email == identifier))
    )
    user = result.scalars().first()
    if not user:
        return False
    if not bcrypt.checkpw(password.encode("utf-8"), user.hashed_password.encode("utf-8")):
        raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="Incorrect username or password")
    return user
```

```tsx
import { useState, type FormEvent } from 'react';
import { Link, useNavigate } from 'react-router-dom';
import { getErrorMessage } from '../api/client';
import AuthLayout from '../components/AuthLayout';
import Button from '../components/ui/Button';
import ErrorBanner from '../components/ui/ErrorBanner';
import Field from '../components/ui/Field';
import { useAuth } from '../context/AuthContext';

export default function RegisterPage() {
  const { register } = useAuth();
  const navigate = useNavigate();
  const [username, setUsername] = useState('');
  const [email, setEmail] = useState('');
  const [fullName, setFullName] = useState('');
  const [password, setPassword] = useState('');
  const [confirmPassword, setConfirmPassword] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [submitting, setSubmitting] = useState(false);

      setSubmitting(false);

        <Field
          label="Full name"
          value={fullName}
          onChange={(event) => setFullName(event.target.value)}
          required
          autoFocus
        />
        <Field
          label="Username"
          value={username}
          onChange={(event) => setUsername(event.target.value)}
          required
        />
        <Field
          label="Email"
          type="email"
          value={email}
          onChange={(event) => setEmail(event.target.value)}
          required
        />
        <Field
          label="Password"
          type="password"
          value={password}
```
